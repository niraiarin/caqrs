## Findings (round 1, on `69cce53`)

| Severity | Finding | Disposition |
|---|---|---|
| major | `enable_live_orders_after_human_approval(env_token=...)` accepted any env-var name. A caller could pass `env_token="PATH"` plus `cli_confirmation_token=$PATH`, flipping `enable_live_orders=True` without using `LIVE_BROKER_*` — confused-deputy reuse of unrelated env vars. | **fixed-before-merge** in `31f4198`: method validates `env_token.startswith("LIVE_BROKER_")` and raises `RuntimeError` otherwise. New regression test `test_enable_live_orders_rejects_non_live_broker_env_token` pins the constraint. |
| major | The code claimed byte equality but both gate paths normalised the env value with `.strip()` (`live_broker_alpaca.py:161`, `:422`). `LIVE_BROKER_ENABLE_LIVE_ORDERS=" secret "` plus CLI input `secret` would have succeeded. | **fixed-before-merge** in `31f4198`: removed `.strip()` from both the method's env read and `_main`'s. The CLI now removes only the trailing newline `readline()` appends, preserving all other bytes. New regression test `test_enable_live_orders_does_not_strip_env_value` pins exact equality (including surrounding whitespace). |
| minor | The CLI uses `sys.stdin.readline()` and echoes a prompt to `stdout`; it does not require a TTY or use `getpass`. Piped invocation (`echo "$LIVE_BROKER_ENABLE_LIVE_ORDERS" \| ... confirm-live`) works, increasing shell-history / process-logging mistake surface. The PR does not print the secret, so this is not an immediate leak. | **accepted as documented trade-off**. Method docstring now explicitly states the gate is "operator-friction, not a security primitive against compromised shell". Per ADR-0008 the kill switch + per-broker daily loss cap are the defense-in-depth layers against malicious paths; the env+CLI gate's role is preventing **accidental** live enablement. A future `getpass`-based no-echo path is a follow-up but does not block the safety contract. |

## Verdict (post-fixes)

**APPROVE_WITH_NITS** — the two majors are addressed structurally (env_token prefix validation; exact byte equality without `.strip()`), and regression tests pin the new invariants. The minor (TTY echoing) is a known trade-off documented in the docstring.

Per ADR-0008 §"Implementation checklist" P4 PRs additionally require **human review before merge — non-negotiable**. This verifier report does not replace that gate.

## Unchecked risks

- Codex sandbox could not run gates; orchestrator confirmed locally: `just ci` → 875 passed (+8 from baseline 867), 5 xfailed (pre-existing).
- The `getpass`-based no-echo input remains a follow-up. The current `readline()` path is correct for tests (StringIO injection) and acceptable for accidental-enablement protection; it is not a defense against malicious shell access.
- `_main` and the broker method both read the env var separately; if the env value changes between them, the method's strict comparison correctly fails. After Codex's findings were fixed there is no race that could produce a false success.
- The Alpaca SDK integration (real REST submission, websocket fills, `BROKER_LIVE_SUBMITTED/FILLED/CANCELLED` emission, `alpaca-py` optional dep, `LICENSE_AND_TOS.md` row) remains the next slice. The Alpaca submission path inside `LiveBrokerAlpaca.execute()` still raises `NotImplementedError` — `enable_live_orders_after_human_approval` flips the flag, but execute() will surface the SDK gap immediately.
- `env_token` defaults to `LIVE_BROKER_ENABLE_LIVE_ORDERS` (matches the `_CONFIRM_LIVE_ENV_VAR` constant the CLI uses). If an operator overrides the default, both the CLI invocation and the method call must use the same name; the prefix-validation guards against trivial confused-deputy abuse but not against operator-side mismatch (which raises a normal env-not-set error).

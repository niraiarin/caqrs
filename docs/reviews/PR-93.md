## Findings

| Severity | Description | Disposition |
|---|---|---|
| minor | Trigger 5 (≥ 200 LOC) is a coarse heuristic. `scripts/verify.py` itself triggers it on its own debut PR. Codex's strategic recommendation was specifically that `just verify` enforce *local* preconditions; a self-triggering script is structurally acceptable (the verifier-report demand is genuine — 325 LOC of new tooling that affects future PR gating IS judgment-laden) but worth flagging so future contributors don't expect a script-only PR to slip through. | accepted (deliberate; the dogfood works) |
| minor | The trigger-5 LOC count includes `scripts/` insertions but excludes `tests/`, `docs/`, and lockfiles. ADR-0007 §5 says "≥ 200 lines of code (excluding tests/, docs/, lockfiles)". `scripts/` is arguably tooling rather than "code" in the production sense; future contributors may want `scripts/` excluded too. The current behaviour is conservative (more triggers fire), which is the safer default for an audit gate. | accepted (conservative default; can be narrowed in a follow-up if false-positive rate is too high) |
| minor | Trigger 3 (type-contract) heuristic uses substring search (`"Protocol):"`, `"(BaseModel)"`, `"(StrictBaseModel)"`). It will miss multi-line class signatures and import-renamed bases (e.g. `from caqrs.schemas.common import StrictBaseModel as _Base; class X(_Base): ...`). Acceptable for the current codebase style (no such renames exist) but documented as a known limitation here. | accepted (documented) |
| minor | `_resolve_pr_number` calls `gh pr view` without specifying which PR; `gh` defaults to "the PR for the current branch". On a branch with multiple open PRs this could pick the wrong one, but the convention in this repo is one PR per branch. | accepted |
| minor | `subprocess.run` calls do not set a timeout. `git diff` and `gh pr view` should be near-instantaneous; a hung gh process would block the verifier. Worth adding a `timeout=30` if observed in practice. | follow-up issue if observed |

## Unchecked risks

- **No automated test for `verify.py`** — the script is its own verification (running it on the dogfood case is the smoke test). A future test could spin up a synthetic git tree and assert trigger detection on each ADR-0007 case; out of scope for this PR.
- **`gh pr view` dependency** — `_resolve_pr_number` requires the GitHub CLI installed and authenticated. The script degrades to "skip the verifier-report check" when `gh` is missing; this is the right behaviour but means the local-only contributor (no GitHub) gets a weaker check.
- **Trigger detection is heuristic, not authoritative.** The orchestrator and human reviewer remain the final arbiters; `just verify` is a checklist, not a gate.
- **Same-family self-review.** Codex cross-family was unavailable earlier in this session due to a quota error; the rest of the 6-task sequence has the same disclosure. For tooling-only PRs the same-family review is acceptable per ADR-0007.

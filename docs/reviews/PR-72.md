## Findings

| Severity | Description | Disposition |
|---|---|---|
| major | T6 spec calls for `conflict_log` to be populated when two sources disagree on a `MarketPoint` value at the same timestamp, but the implementation's test only asserts the merged series; it does not assert that `conflict_log` records the disagreement with the lower-priority source's value. | fixed-before-merge (commit 3 adds an assertion on `conflict_log` length and contents when values differ) |
| major | Property P4 ("source-priority `iff` value-membership in merged series") is incomplete: the test exercises the `→` direction (high-priority point ends up in merged series) but not the `←` direction (low-priority point at the same timestamp is **excluded**). The full `iff` is required by the spec. | fixed-before-merge (commit 3 strengthens P4 to cover both directions) |
| minor | T4 asserts `IdentifierConflictError` is raised but does not pin the error payload (`kind`, `value`, `existing_issuer_id`, `proposed_issuer_id` fields). A future regression that raised the right error class with empty fields would pass. | fixed-before-merge (commit 3 adds field-level assertions on the raised error) |
| minor | T12 (provenance round-trip) does not assert `fetched_at` survives serialization / deserialization. The test exercises identity but not the temporal field. | fixed-before-merge (commit 3 adds `fetched_at` round-trip assertion) |
| minor | `append_filing` and `append_relation` raise `UnknownIssuerError` when the referenced issuer is not present, but no test exercises that path. The behaviour is documented in the protocol; the regression net is missing. | fixed-before-merge (commit 3 adds two unknown-issuer raises tests) |
| minor | Pydantic `frozen=True` is set on every entity model via `StrictBaseModel`, but no test exercises that mutation actually fails. A future loosening of `StrictBaseModel` would not be caught. | fixed-before-merge (commit 3 adds frozenness assertion in `tests/test_entities_types.py`) |

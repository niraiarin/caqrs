## Unchecked risks

- **Hermeticity of `uv run --with pyyaml`**. The `--with` flag resolves
  `pyyaml` from PyPI at every invocation rather than from a pinned manifest.
  In a CI environment with cached uv resolutions this is fine; in a cold
  cache or behind a network policy it is a soft dependency on PyPI
  availability. The first `minor` finding above raises this; the verifier
  did **not** stress-test the failure mode.
- **No property-based test on the AST visitor.** `_extract_traces_args`
  (lines 254-271) handles `pytest.mark.traces(...)` calls but would silently
  ignore `from pytest import mark; @mark.traces(...)` or
  `import pytest as p; @p.mark.traces(...)`. The repo today writes the
  decorators in the canonical form (verified across all 46 sites), so this
  is not a defect; if a contributor uses one of the alternative imports,
  the marker becomes invisible to the gate. Not in scope to fix in #80.
- **Coverage as a downstream Task**. The verifier did not measure how many
  formalized REQ-IDs would lack `@traces` if bidirectional completeness were
  enabled today. The PR body cites 37 of 165 (22 %) covered; the verifier
  re-confirmed the numerator and denominator from the script's own success
  output. The complementary set of 128 formalized-or-tacit REQ-IDs without
  any reverse marker is not enumerated here; doing so requires running the
  checker in a hypothetical *strict* mode that does not yet exist.
- **macOS-only sandbox.** Gates were re-executed on macOS / Python 3.13 via
  `uv`. Linux × Python 3.12 (the other CI matrix cell) was not reproduced
  by this verifier. Per ADR-027 paper-scope policy this is acceptable; the
  formal CI run on the PR is the cross-platform authority.
- **No cross-family verifier.** Per ADR-027 v0.1.0, paper-scope PRs accept
  intra-family review; this verifier is Claude (orchestrator-family). A
  live-broker change would escalate; not applicable here.

## Findings (round 1, on `a959e28`)

| Severity | Description | Disposition |
|---|---|---|
| major | `_is_live_broker()` was too weak: `hasattr(broker, "enable_live_orders")` only checks the NFR-1 flag exists; it does not prove `set_cycle_id()` exists or that BROKER_LIVE_* events will reach the runner's EventLog. A future paper-broker variant that grew an `enable_live_orders` attribute would crash at `set_cycle_id` or silently lose its `BROKER_EXECUTED` audit event. | **fixed-before-merge** in `5dbe1ed`: added `LiveBrokerProtocol(Protocol, runtime_checkable)` to `caqrs.execution.protocol` bundling `enable_live_orders` + `attach_cycle_context` + `detach_cycle_context` + `execute`. CycleRunner now uses `isinstance(broker, LiveBrokerProtocol)` so all surfaces are checked simultaneously; the duck-typed accidental match Codex flagged is structurally impossible. |
| major | `LiveBrokerAlpaca._cycle_id` was shared mutable state. `set_cycle_id()` immediately before `execute()` was sufficient for the default-off short-circuit but not for concurrent runs against the same broker instance — another runner could overwrite the field while the first awaited paper pre-flight. | **fixed-before-merge** in `5dbe1ed`: replaced `set_cycle_id` with explicit `attach_cycle_context(cycle_id, event_log)` + `detach_cycle_context()` lifecycle. The runner pairs them in `try`/`finally` so an exception inside `execute()` does not leave broker state stuck. The attach is **non-reentrant**: a second `attach` while a context is live raises `RuntimeError("non-reentrant")`. New regression test `test_live_broker_attach_detach_pairs_per_execute` pins the contract. Concurrent runners against the same broker now fail fast rather than silently mis-attribute events. |
| major | Event-log sharing was implicit and easy to miswire: if `LiveBrokerAlpaca` was constructed with `event_log=None` or a different EventLog, the runner suppressed `BROKER_EXECUTED` and the runner's own log contained no broker outcome — violating the audit intent of NFR-LIVE-BROKER-7 even though the code "succeeded". | **fixed-before-merge** in `5dbe1ed`: removed `event_log` and `cycle_id` from `LiveBrokerAlpaca.__init__`; the runner injects them per-cycle via `attach_cycle_context`. Tests that want emission outside a runner attach manually for symmetry. The miswiring scenario is structurally gone — the EventLog the runner uses is exactly the EventLog the broker emits into. |
| minor | Coverage only proved the default-off rejection path. Missing: kill-switch engaged path through CycleRunner, attach-detach pair regression. | **fixed-before-merge** in `5dbe1ed`: added `test_live_broker_kill_switch_engaged_emits_rejected_not_executed` (kill-switch path) and `test_live_broker_attach_detach_pairs_per_execute` (lifecycle invariant). Total: 3 integration tests covering 3 distinct short-circuit paths. The FILLED path remains legitimately N/A pending Alpaca SDK integration. |

## Verdict (post-fixes)

**APPROVE_WITH_NITS** — the refactor in `5dbe1ed` directly addresses every Codex finding. The `LiveBrokerProtocol` runtime-check makes accidental classification impossible; the attach/detach lifecycle eliminates the shared-mutable-state hazard; runner-injected event_log eliminates the miswiring path.

Per ADR-0008 §"Implementation checklist" P4 PRs additionally require **human review before merge — non-negotiable**. This verifier report does not replace that gate.

## Unchecked risks

- Codex sandbox could not run gates; orchestrator confirmed locally: `just ci` → 867 passed (+3 from baseline 864), 5 xfailed (pre-existing).
- The `enable_live_orders_after_human_approval` env-var + CLI workflow remains a stub (NotImplementedError) until the Alpaca SDK integration. The structural lock — production code MUST go through this method — holds today by raising; the real workflow is the next follow-up.
- `LiveBrokerProtocol` requires `runtime_checkable`. If a future Protocol member becomes a non-trivial class attribute, `isinstance` semantics could shift. Current members (`enable_live_orders` instance attr + 3 method-shaped) are well-formed.
- The non-reentrant attach guards single-broker concurrency but does NOT prevent intra-cycle re-execution (e.g. retry on transient error). A retry would need to attach again, which currently raises. If retry semantics are added later, the lifecycle will need to support an `attach`-`detach`-`attach` sequence within the same cycle. Out of scope for this PR.

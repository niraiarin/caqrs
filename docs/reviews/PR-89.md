## Algorithm review

I walked the implementation looking for off-by-one and scope-leak bugs.

- **Module discovery (`_walk_modules`)**: paths under `__init__.py` correctly collapse to the package's dotted name. `*.py` files become `<dir>.<stem>`. `SyntaxError` / `UnicodeDecodeError` on parse fall through silently — these are caught by the standalone mypy gate, so the lint shouldn't double-report.
- **Import edge extraction (`_extract_imports`)**: For `from a.b import c, d`, three edges are emitted (`a.b`, `a.b.c`, `a.b.d`). Downstream BFS prunes any whose target isn't in the audit's graph, so over-reporting is harmless. Relative imports use `current.split(".")[:-node.level]` for the base — correct for `from . import X` (level=1) inside `pkg.subpkg.broker` (becomes `pkg.subpkg`).
- **Env-read collection (`_EnvReadCollector`)**: scope stack pushed/popped per `FunctionDef` / `AsyncFunctionDef`. Constants resolve directly; `Name` nodes resolve via the scope stack walked outermost-to-innermost. Caveat: lookup is *innermost-first* via `reversed(self.scopes)`, which is correct for shadowing (inner default beats outer default). The audit deliberately treats `args.kw_defaults` entries that are `None` (no default) as "skip" rather than "dynamic" — those parameters cannot be resolved by the lint without a full type-flow analysis, so this is correct conservative behaviour.
- **BFS (`_bfs_reachable`)**: iterates targets in `sorted(info.imports)`, building deterministic paths. Each module is recorded with its import chain at first-discovery time, which is the **shortest** chain (BFS invariant). If the same target is reached via a longer alt path later, the longer path is discarded — by design, the report shows the shortest leak chain.
- **Sort stability**: `violations.sort(key=lambda v: (v.boundary, v.env_var, v.site_module))`. Stable across Python versions; deterministic across runs. ✓

## NFR-LIVE-BROKER-2 fidelity

ADR-0008 §NFR-LIVE-BROKER-2 specifies three threshold predicates:

1. PaperBroker reads zero `LIVE_BROKER_*` env vars — **covered** by `DEFAULT_BOUNDARIES[0]` and `test_real_codebase_passes_default_paper_broker_boundary`.
2. LiveBroker reads zero data-side env vars (`JQUANTS_*` / `EDINET_*` / `EDINETDB_*` / `POLYMARKET_*` / `YFINANCE_*`) — **structurally covered** by `DEFAULT_BOUNDARIES[1]`. Currently skip-silently because the LiveBroker module doesn't exist yet (P4 pending). The skip-silently contract is explicitly tested by `test_missing_boundary_module_skips_silently`.
3. All live creds encrypted at rest via dotenvx — **out of scope** for this lint. Encryption-at-rest is a deployment concern (the encrypted `.env` file lives outside the source tree) and cannot be verified by static graph analysis. NFR-COMPLY-3 (manual audit) covers this. The PR description should mention this limitation; the verifier report does so here.

The audit additionally surfaces the import chain that produced a leak — beyond the bare predicate the NFR demands. This is value-added reporting, not a deviation.

None of the existing CAQRS code uses this pattern, but a future helper might. The pattern would be reported as a dynamic read (`name=None`) and silently skipped. | minor | The `Justfile` `ci` recipe runs `lint-creds` after `tos` and before `test`. This means a failing credential-isolation gate aborts before the test suite runs. ## Unchecked risks

- **Codex cross-family review unavailable**: this self-review by Claude Code Opus 4.7 is honest about being same-family. Per ADR-0007 the cross-family option is preferred; Codex hit a usage limit during the review attempt. A follow-up Codex pass is recommended before any P4 work depends on this lint.
- **Module-level constant indirection**: env-var names defined as module-level constants (e.g. `_KEY = "LIVE_BROKER_API_KEY"; os.environ.get(_KEY)`) are not statically resolved by the audit and would be silently skipped as `name=None` dynamic. None of the current CAQRS code uses this pattern, but a future contributor might. A follow-up could extend the resolver to walk module-level `Assign` nodes; out of scope for this PR.
- **Reflective `os.environ` access**: patterns like `getattr(os.environ, "get")(name)` or `(os.environ).get(name)` would not match the AST shape the audit looks for. NFR-SEC-1's manual audit per release is the safety net.
- **Encryption-at-rest**: NFR-LIVE-BROKER-2's third predicate (dotenvx encryption) is a deployment concern and not enforceable by static graph analysis. The lint's scope is the import-graph reachability check; the encryption is owned by NFR-COMPLY-3 and the deployment runbook.
- **CI `lint-creds` ordering vs. cache**: in `.github/workflows/ci.yml` the `lint-creds` step runs after `Sync deps` (uv install) but the `--frozen` flag means the lint reads from the locked `uv.lock`. If `uv sync --frozen` is added/changed in a future PR the lint's interpreter must still see `caqrs.lint.credential_isolation`; verified today by running `just ci` locally.
- **Synthetic-fixture `_write_module` helper**: the test helper writes empty `__init__.py` for ancestors, but does NOT write an `__init__.py` *inside* the package containing the boundary module. The audit handles this because `_walk_modules` discovers `*.py` files directly. If a test fixture wrote a deeply nested package without intermediate `__init__.py`, Python's import system would not find it — but the audit reads paths directly, so it works. This is an asymmetry between Python imports and the audit; for the audit's purpose it's correct.

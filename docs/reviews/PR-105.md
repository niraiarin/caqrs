## Round 1 findings

| Severity | Finding | Round 2 disposition |
|---|---|---|
| major | `except Exception` was too broad — would silently retry forever on fatal config/programming bugs (`InvalidURI`, `InvalidHandshake`, 4xx `InvalidStatus`, `TypeError`, persistent `JSONDecodeError`). Codex's recommendation: narrow to `EOFError`/`OSError`/`asyncio.TimeoutError` + websockets-library `ConnectionClosed` and `InvalidStatus(5xx)`. | **fixed** — `_RETRYABLE_TRANSPORT_ERRORS = (OSError, TimeoutError, EOFError)` plus a late-imported `_is_websockets_transient(exc)` that recognizes `ConnectionClosed` and `InvalidStatus(5xx)`. Anything else now propagates. New test `test_trade_updates_stream_propagates_fatal_exceptions` pins this. |
| minor | No regression test for `asyncio.CancelledError` propagation. Today it works (CancelledError is BaseException, escapes `except Exception`), but a future widening to `BaseException` would silently break task cancellation. | **fixed** — `test_trade_updates_stream_propagates_cancelled_error` raises CancelledError on iter and asserts it escapes. |
| minor | Malformed JSON frame mid-stream triggered full reconnect, conflicting with `alpaca_stream.consume()`'s defensive drop-and-continue posture for downstream parse failures. | **fixed** — `json.loads` is now in an inner `try/except JSONDecodeError: continue` block so one bad frame doesn't tear down the stream. Test `test_trade_updates_stream_drops_malformed_json_and_continues` covers this. |

## Codex round 1 confirmed-correct behaviors

- **Auth failure**: `_auth_authorized()` only accepts `data.status == "authorized"`; `AlpacaWebSocketAuthError` is raised inside the `async with`, the outer handler re-raises before the transient retry path. Correct.
- **Listening ack drain**: not strict-validating the ack shape is the right pragmatic call given Alpaca's drift history. The safety-critical gate is auth, not the exact echo.
- **`_default_connect`**: runtime-plausible. websockets 15/16 docs confirm `connect()` is usable as an async context manager. The `# type: ignore[return-value]` is a typing/protocol mismatch, not a runtime bug.

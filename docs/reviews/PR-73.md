## Findings

| Severity | Description | Disposition |
|---|---|---|
| major | First-pass implementation produced 7 test failures in `tests/test_entities_duckdb.py`, all rooted in `Issuer.identifiers` ordering inconsistency between backends (InMemory preserved insertion order; DuckDB returned SQL `ORDER BY`-driven order). The two backends produced non-equal `Issuer` instances for the same legal entity. | fixed-before-merge (resolved by adding a `model_validator(mode="before")` to `Issuer` that canonically sorts `identifiers` by `(kind.value, value)`; both backends now produce equal `Issuer` instances; one new invariant test in `tests/test_entities_types.py` pins the order) |
| minor | Test fixtures use `cast(duckdb.Connection, ...)` because the `duckdb` library has no `py.typed` marker yet. Documented in the PR body as the only `cast` in new code. | accepted (external library limitation; revisit when DuckDB ships type stubs) |
| minor | `init()` is documented as idempotent and writes schema version `1`; the test for unsupported schema version raises `EntityStoreError` but does not pin the error message string. A future change to the message would not be caught. | wontfix (message-string pinning is brittle; the error class plus the version number assertion are the contract) |
| minor | Concrete extras (`list_all_issuers`, `list_all_filings`, `list_all_relations`) live on `DuckDbEntityStore` but not on the abstract `EntityStore` Protocol. Documented as intentional implementation-specific helpers for round-trip tests and ad-hoc inspection. | accepted (Protocol surface stays minimal; concrete-only methods are flagged as such in the source docstring) |

## Unchecked risks

- **No independent verifier review**. ADR-027 v0.1.0 specifies an
  intra-family Codex verifier for paper-scope work and a cross-family
  + human-gate for live-broker scope. Phase E2 is paper-scope and a
  new-module addition, which under ADR-0007 (this commit's enabling
  ADR) requires a verifier report. **At original merge time, no such
  review was conducted**; the Codex instance involved acted as
  implementor and follow-up fixer for the identifier-ordering issue,
  not as a verifier. This artifact is the orchestrator's
  reconstruction and self-assessment, **not** an adversarial review.
  See PR #71 / PR #72 reports for what an independent verifier review
  looks like; the absence here is the precise gap ADR-0007 closes for
  future PRs.
- **Persistence corner cases**: schema version downgrade (writing a
  file with version `1` and opening with future code that expects
  version `0`) is not exercised. Not in scope for E2 (no migration
  framework yet).
- **Concurrency**: DuckDB's single-writer-per-file semantics are
  inherited; no test exercises concurrent open from two processes.
  Not asserted as a contract.
- **Round-trip test (T11) coverage breadth**: the T11 fixture
  populates 2 issuers, 6 identifiers, 4 MarketPoints across 2
  priorities, 2 filings, 2 relations. Edge cases beyond that
  (empty store, 0-relation issuers, very large MarketSeries) are
  not exhaustively pinned by the round-trip; the E1 in-memory tests
  cover the empty / minimal cases and the type-layer validator now
  guarantees backend equivalence, so the round-trip's role is
  end-to-end persistence verification rather than full coverage.
- **Quality-gate re-execution by an independent reviewer**: not
  performed. Local + CI gates were the authoritative confirmation.

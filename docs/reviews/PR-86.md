## Spec deviations (declared)

1. **`ReconcilerResult.provenance`**: Spec §C lists 4 fields (`upserted, skipped, conflicts, dry_run`). Step 2 adds `provenance: tuple[Provenance, ...] = ()`. The motivation: spec §A.3 / §A.3-footnote leave the question of *where* `Provenance` is exposed open ("on a sentinel `MarketPoint` if the loader writes one, otherwise on the `Issuer`-attached provenance per #85's design"); `Issuer` has no provenance field and is out-of-scope for modification. Returning provenance via the result is the least-invasive choice. Default is `()` so the field is optional in test constructions.
2. **`EdinetDbCompany.jcn`**: Additive optional field added so ENT-RECON-A6 / T28 can express the JCN identifier. See findings table.
3. **EDINET DB end-of-stream detection**: Spec §C says "advances pages until an empty page or a `next_page=None` token". The `EdinetDbCompaniesList.meta.pagination` does not surface a `next_page` token; it has `(page, per_page, total)`. The implementation prefers `total` (running sum >= total) when present, and falls back to `len(data) < per_page` when total is absent. T30's stub provides `total=1500`; T21's stub provides `total=1200`; both walk all pages.

- **Dry-run conflict-detection accuracy**: the simplified `_try_upsert` collapses the dry-run path: it detects display-name conflict (T25-style) but does not re-scan for foreign-identifier conflicts (e.g. an overlap on a non-primary identifier where `_find_existing_owner` already picked a different first hit). For the PR's tested inputs this never occurs; for adversarial inputs the dry-run might under-report conflicts that a real run would surface. A property test could close this gap; deferred.
- **EDINET DB client `from_env` was not exercised**; tests pass the api_key directly. The `from_env` codepath has its own existing tests outside this PR.
